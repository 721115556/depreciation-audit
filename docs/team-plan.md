# 四人分工与工作计划

## 共同目标和约定

交付可重复运行的折旧复核程序和四张结果表，并准备可解释、可复核的演示。以题目说明和输出模板为依据；AI 生成的代码、公式和结论都需要成员核验。

- 建议统一使用 Python；具体依赖和运行方式由两位开发成员在第一轮确认，并写入 README。
- 输入为台账 Excel，输出为新的结果 Excel。保留每一条原始记录，不按资产编码去重。测试数据中观察到编码重复，应保留来源行号以便追溯。
- 差异额为“账面月折旧 − 测算月折旧”。采用题目正文中的“绝对差异额大于 1 元且绝对差异率大于 1%”判断差异异常，附加异常标志单独触发；示例代码只判断金额，需记录这一不一致。
- 测算值为零时差异率无法计算，可显示“不适用”或空值，并另行标记账面有折旧等需要复核的情况。此为团队暂定口径，须在结果和说明中注明。
- 已使用月数、累计折旧的时点及最后一个月计算顺序可能影响尾差。测试负责人记录假设及案例，有机会时向赛事组织方确认。
- 资产状态与异常原因分开记录。同一资产可能同时已提足且存在账面异常，统计时说明分类是否互斥以及异常数口径。
- 本仓库公开，未经确认不上传赛题原始台账、模板、输出结果或账号凭据；使用自行构造的数据测试。

## 成员与职责

| 成员 | AI 工具 | 负责内容 | 主要交付 |
| --- | --- | --- | --- |
| A：计算负责人 | Trae | 输入校验、折旧重算、差异及异常判断、技术整合 | 计算模块、接口说明、单元测试支持 |
| B：输出负责人 | Trae | Excel 输出、异常标红、四表汇总、运行入口 | 输出模块、运行入口、使用说明初稿 |
| C：规则与测试负责人 | GPT Plus | 解析赛题规则、设计独立测试、核对算法和输出 | 规则表、测试案例、复核记录 |
| D：项目与展示负责人 | GPT Plus | 跟进进度、组织交叉评审、整理文档和答辩 | 进度表、验收清单、演示材料 |

A 负责技术合并，D 负责组织。每位成员对自己提交的内容负责，AI 是辅助工具。C 和 D 的文档或测试产出也放在各自分支上提交。

## 第一轮：明确规则和接口

目标：让四人同时开始工作，避免接口不一致。

- **A**：梳理输入字段、数据类型和计算流程；提出计算函数的输入输出结构，列出缺失值和非法值处理建议。
- **B**：检查成果模板，列出四张表的字段、格式和汇总口径；与 A 确定计算结果如何传给输出模块。
- **C**：形成规则表和至少 10 个手算案例，覆盖正常折旧、提足、最后一个月、报废、原值为零、残值异常、应提未提、差异阈值边界、零分母和重复编码。指出需要确认的题意。
- **D**：建立任务看板或共享进度表，记录人员、负责人、交付时间和阻塞；整理演示目标及与评分项的对应关系。

验收：四人确认一份字段与接口约定；每个特殊情形都有暂定规则、测试输入和预期结果。争议标为待确认。

## 第二轮：独立实现和验证

- **A**：实现逐行计算、输入校验和异常原因输出；提供独立可调用函数。非法值应可追溯，不能静默丢行。
- **B**：基于约定的模拟结果实现四表输出、整行标红、分类汇总和基本排版；提供运行入口。
- **C**：将第一轮案例转成可重复运行的测试或清晰的手工核对表，独立检查 A 的结果，并验证 B 的汇总和标红。记录输入、预期、实际和结论。
- **D**：编写 README 的安装与使用草稿、准备一键演示流程；确认输出是否覆盖评分要求，维护问题清单。

验收：小样本端到端运行成功；规则案例的结果可追溯。开发者修复问题后由测试负责人复核。

## 第三轮：整合、大数据和体验

- **A**：整合模块，检查重复编码、异常数据和每行记录是否保留，修复计算问题。
- **B**：检查四表一致性、分类合计与明细对账、异常行标红和工作簿可读性。
- **C**：在本地使用赛题测试台账执行全量测试，记录资产条数、运行时间、异常数量、未处理记录和抽样复核结果；不将原始数据或结果上传公开仓库。
- **D**：邀请另一名成员按 README 从零运行，收集问题；准备展示材料，区分必做功能、可选加分项和尚未解决的问题。

验收：输入行数与输出明细行数核对一致；分类汇总能对回明细；异常汇总与异常标记一致；约 1.2 万条数据处理完成且无崩溃。记录实测耗时，不预先承诺“秒级”。

## 第四轮：复核、演示与提交

- **A 和 B**：修复验收问题，冻结版本，确认依赖与运行命令。
- **C**：复跑关键案例和全量对账，形成最终测试记录，列明未解决事项和假设。
- **D**：组织一次完整演示，核对赛事提交要求，汇总代码、说明和允许提交的成果。

最终检查：计算与异常口径有说明；四表完整；异常标红正确；统计可核对；运行步骤可复现；题意不明确之处有记录；公开仓库没有未经授权的数据或凭据。

## 可直接使用的 AI 提示词

使用前请结合实际情况补充资料，附件只在允许使用和上传时提供。提示 AI 先说明假设和问题，再生成结果；任何数据或代码均由成员复核。

### A：Trae，计算模块

```text
你是 Python 开发助手。请根据仓库 README 和 docs/team-plan.md 实现固定资产当月折旧重算模块。
输入字段为资产编码、资产描述、资产分类、原值、残值、资本化日期、计划使用年、已使用月数、当月账面折旧、累计折旧、报废标识，并保留来源行号。
按赛题直线法与特殊情况计算；差异为账面减测算。按金额大于 1 元且差异率大于 1% 判断差异异常，并分别记录附加异常原因。不能按编码去重。
先列出函数接口、计算顺序和不明确的假设，包括累计折旧时点、最后一个月、零分母、四舍五入和无效输入。然后实现代码，并用自行构造的案例检查边界。
不要把赛题原始文件提交到公开仓库；不要把无法计算的记录静默删除。列出运行方法和剩余问题。
```

### B：Trae，Excel 输出与运行入口

```text
你是 Python 开发助手。请阅读 README 和 docs/team-plan.md，并与计算模块约定输入结果结构。
实现一个输出模块，生成“折旧测算结果、异常资产汇总、分类汇总统计、统计总览”四张表；异常明细整行标红，保留异常原因，金额与差异率格式清晰。
使用自行构造的模拟数据完成开发。确保明细、异常汇总和分类汇总的数量与金额能够核对；将状态和异常标志分开处理。
提供清晰的一键运行方式与错误提示。先说明接口和依赖，再实施；最后展示验证方法和未解决问题。不要上传赛题原始数据或成果。
```

### C：GPT Plus，规则与独立测试

```text
请作为审计测试复核员，根据我提供的赛题说明，整理固定资产折旧重算的规则表。逐条列出输入、计算公式、判断条件、优先级、输出和需要确认的问题。
请设计至少 10 个可手算测试案例，覆盖正常折旧、已提足、最后一个月尾差、报废、原值为零、残值不合理、应提未提、1 元和 1% 边界、测算值为零以及重复编码。
对每个案例给出具体数字、预期结果和计算过程。指出正文异常规则与示例代码的差别，并说明累计折旧时点不明确会如何影响尾差。不要假设模糊规则已经得到官方确认。
```

### D：GPT Plus，整合与展示

```text
请作为四人项目协调员，根据赛题说明、评分标准和当前进度，制作项目验收清单及一次 5 分钟演示方案。
成员分工：A 用 Trae 负责计算，B 用 Trae 负责 Excel 输出和运行入口，C 用 GPT Plus 负责规则和测试，D 用 GPT Plus 负责协调、文档和演示。
请按轮次列出依赖、交付物、负责人和验收方法；演示应展示输入、运行、四张结果表、异常示例、对账和实测耗时。区分已经实现与计划实现的功能，列出需要人工核实的题意和数据公开问题。
```

## Git 协作建议

从最新 `main` 创建个人分支，例如 `feature/calculation`、`feature/excel-output`、`test/rules`、`docs/demo`。每次提交聚焦一件事，通过 Pull Request 描述变更和验证结果；至少由一位其他成员检查，再由 A 或 D 协调合并。合并前检查是否意外包含测试台账、生成的成果文件或凭据。
